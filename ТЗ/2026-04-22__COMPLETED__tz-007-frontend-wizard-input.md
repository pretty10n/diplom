# TZ-007 Frontend мастер ввода

## Status
COMPLETED

## Goal
Реализовать интерфейс ввода данных в формате "общие данные + универсальная строка" согласно `UI_SPEC.md`.

## Business context
Снижение времени заполнения и количества ошибок при вводе исходных данных.

## System context
React + TypeScript, интеграция с backend API.

## Functional requirements
- Шаг 1: ввод общего блока (1 раз на пакет):
  - наименование и шифр;
  - этап;
  - отчетный год и планируемый год.
- Шаг 2: единый экран "Универсальная строка":
  - выбор `Раздел` из справочника;
  - форма определяется автоматически и отображается в readonly-плашке (форма, раздел, будущий номер строки);
  - динамический набор полей по выбранной форме (4/5/6).
- Для форм 4/5/6:
  - поддержать колонки `2,3,4,6,7,8,9,10,13.1,13.2,14,15`;
  - `col11` и `col12` только readonly (авторасчет backend);
  - значения `0` в колонках `6-10` отображать как пусто, `3-4` при `0/пусто` отображать `-`.
- Таблица введенных строк:
  - колонки: раздел, форма, номер строки, наименование, ключевые суммы, статус валидации, действия;
  - действия: редактировать, дублировать, удалить;
  - фильтры: по разделу, форме, статусу.
- Интеграция со справочниками через `GET /api/v1/dictionaries`.

## Non-functional requirements
- Простой UI без перегруженности.
- Валидация обязательных полей на клиенте.
- Обработка UX-состояний: пусто, загрузка, ошибка сети/сохранения, несохраненные изменения, подтверждение удаления, успешное сохранение.

## Acceptance criteria
- Пользователь заполняет общие данные, добавляет строки через универсальный ввод и сохраняет черновик.
- Можно добавить/изменить/дублировать/удалить неограниченное число строк в 4/5/6.
- Для каждой строки форма корректно определяется только по разделу, без ручного выбора формы.

## Edge cases
- Переход между шагами при частично заполненных данных.
- Ошибки API при сохранении.
