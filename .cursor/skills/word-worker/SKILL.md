# Word-worker

## Назначение

`Word-worker` — единая роль для задач по документам Word в проекте:
- генерация и обновление `.docx` из Markdown/данных;
- соблюдение правил оформления (структура, шрифты, интервалы, отступы, содержание);
- модульная сборка (по разделам) и merge-сборка итогового документа;
- поддержка не только дипломов, но и любых учебных/рабочих текстов.

## Когда применять

Применять при запросах вида:
- "написать/перегенерировать диплом/ВКР/курсовую";
- "собрать отчет в Word";
- "исправить содержание, стили, заголовки, нумерацию страниц";
- "сделать отдельные главы + объединить одной командой";
- "унифицировать формат Word для будущих тем".
- Командный запуск профиля: `/diploma-vgtu-md`.

## База правил и навыков (без дублирования)

`Word-worker` использует роутинг через:
- `.cursor/skills/document-governance/SKILL.md` (приоритеты и source-of-truth);
- `.cursor/skills/diploma-vgtu-md/SKILL.md` для профиля `diploma-vgtu`;
- `.cursor/rules/ucheba-otchety-i-diagrammy.mdc` для профиля `academic-report`.

Если пользователь уточнил формат, это уточнение фиксируется в профильном source-of-truth (не дублируется в нескольких файлах).

## Унифицированный режим (не только диплом)

Перед генерацией документа выбрать один из профилей:

- `diploma-vgtu`: ВКР/диплом по правилам ВГТУ и проектным ограничениям.
- `academic-report`: учебный отчет/лабораторная/НИР с академическим стилем.
- `technical-doc`: техническая документация (архитектура, эксплуатация, регламенты).

Жесткий роутинг:
- Если пользователь пишет `/diploma-vgtu-md`, сразу активировать профиль `diploma-vgtu` без дополнительных уточнений.

Если профиль не указан, по умолчанию:
1) определить его из запроса;
2) при неоднозначности спросить у пользователя;
3) не менять уже согласованный формат внутри текущей задачи.

## Единый workflow

1. Собрать требования (структура, объем, язык, формат оформления, наличие диаграмм/таблиц).
2. Проверить/обновить исходные Markdown-файлы разделов.
3. Обновить генераторы (`pycode/*.py`) без нарушения модульности.
4. Пересобрать целевые `.docx`:
   - по разделам (`chapter`, `references`) при точечных правках;
   - `merge` для итогового документа.
5. Проверить результат:
   - структура и порядок разделов;
   - корректность оглавления;
   - соответствие форматированию;
   - отсутствие дублирования и служебного текста.
6. Зафиксировать новые требования формата в профильном скилле.

## Форматирование Word

Нормативы форматирования не дублировать здесь:
- для `diploma-vgtu` брать из `diploma-vgtu-md`;
- для `academic-report` брать из `ucheba-otchety-i-diagrammy.mdc`;
- для `technical-doc` задавать по явному требованию пользователя.

Для профиля `diploma-vgtu` плейсхолдеры ручной вставки визуалов оформлять парой строк:
1) красный КАПС-плейсхолдер в скобках;
2) сразу под ним подпись `Рисунок N. ...` обычным черным текстом.
Если плейсхолдер относится к таблице — использовать подпись `Таблица N. ...`.

При наличии draw.io CLI:
- стараться генерировать часть схем/таблиц через draw.io;
- экспортировать PNG и вставлять их в документ через стандартные image-директивы.

## Структура для дипломных задач

- `ВВЕДЕНИЕ`
- главы основной части (`1`, `1.1`, `1.2` ... `3.x`)
- `ЗАКЛЮЧЕНИЕ`
- `СПИСОК ЛИТЕРАТУРЫ`
- приложения (если требуются)

`ВВЕДЕНИЕ` и `ЗАКЛЮЧЕНИЕ` не нумеруются как главы.

## Качество результата

Перед завершением задачи проверять:
- документ собирается без ошибок;
- содержание соответствует фактической структуре документа;
- формат единообразен между отдельными главами и merge-версией;
- текст без метакомментариев об ИИ;
- требования пользователя сохранены в навыке/правилах для повторного использования.
